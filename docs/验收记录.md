## 实际环境

- Apple Silicon Mac，Xcode 27.0；iPhone 17 Pro / iOS 27.0 模拟器已安装并启动应用。
- PostgreSQL 17 + pgvector、NATS 2.11、OPA 1.4.2 在 Docker 中实际运行，仅绑定本机端口。
- llama.cpp 8460，官方 Qwen3-0.6B-Q8_0 GGUF；仅为链路验证模型，不作为最终质量承诺。
- `homeai_runtime` 为实际业务库；`homeai_test` 为集成测试库。最初的 `homeai` 保留早期测试数据，没有删除。
- 本机启动地址：API `https://localhost:58443`，模型 `http://127.0.0.1:58080`。

## 2026-09-17 多步骤执行与恢复

- 显式工作流支持最多 16 步、步骤预算、前序结果引用、任务截止时间、外部调用超时和有限只读重试；每步独立持久化并检查策略及审批。
- PostgreSQL 连接级任务锁覆盖网络调用与事务提交，避免多 worker 重复执行；启动不再批量将其他进程中的任务标为未知。
- 已完成步骤不重放；不明外部副作用只能人工核对。核对依据加密保存，浏览器要求近期密码/TOTP；确认未执行后高风险步骤重新审批，过期或已取消任务禁止重新执行。
- 真实 PostgreSQL/OPA 测试覆盖步骤结果引用、锁竞争、步骤边界恢复、审批取消、过期未知结果及 TCP 连接失败重试预算。未通过测试实际发送邮件，不把外部发送当作已验证。
- 网页任务列表新增步骤详情、取消与人工核对；Cron 使用相同多步骤工作流。
- 自然语言自主多轮 Agent、费用预算、Skill 条件/补偿仍未完成；完整目标保持进行中。

本轮最终回归为 36 项通过，包含真实工具结果进入真实 llama.cpp 的多步骤流程和过期审批收尾；管理后台构建通过。
