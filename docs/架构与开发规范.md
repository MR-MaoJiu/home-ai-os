# 架构与开发规范

## 不可绕过的边界

1. Core 拥有规范数据。SDK、MCP、模型、文档与网页输出均为不可信数据。
2. Provider 不得导入 `homeai`、持有 Core 数据库凭据或挂载 Docker Socket。
3. 用户与家庭身份来自设备验证后的 Actor，不接受请求正文覆盖。
4. 工具风险来自核心注册表。审批必须绑定用户、调用参数摘要和有效期。
5. 模型调用与副作用必须经过策略；OPA 故障必须失败关闭。
6. 云端不能以本地故障为理由自动降级。当前未完成完整脱敏链，只接受显式公开资料的固定指令。
7. RLS 是第二道防线；API 查询仍要约束用户与家庭。运行账号不得持有 SUPERUSER/BYPASSRLS。
8. Outbox 与业务变更同事务；外部结果不明进入待核对，不自动重放。
9. 密钥、会话、附件和模型上下文不得进入普通日志。请求校验错误不回显输入值。
10. 不将个人事实写入模型权重。候选未经确认不得覆盖规范记忆。

## 当前部署边界

- 核心 API 与 worker 为同一代码包的独立进程，PostgreSQL 规范存储。
- llama.cpp 在 Mac 原生运行，使用 Metal；容器运行 PostgreSQL、NATS 与 OPA。
- 外部 SDK 在独立 Provider 进程运行；开发网络许可检查不等于操作系统网络隔离。
- 生产 sandboxd、rootless/gVisor、代理出站、签名/SBOM 与资源限制尚未实现，不得用配置文字冒充安全控制。

## 密码学与会话

每个载荷生成独立 DEK，AES-256-GCM 加密正文，再以主密钥包装 DEK；AAD 绑定所有者、用途与资源 ID。主密钥文件仅用于开发，自身需要 FileVault/LUKS 与独立备份。当前没有生产密钥轮换服务。

设备证明内容依次为时间、nonce、HTTP 方法、编码路径及查询、正文 SHA-256、访问令牌 SHA-256，以换行分隔。ECDSA 使用 P-256/SHA-256 和 DER 签名。nonce 不可重用，允许 60 秒时钟偏差。访问令牌 15 分钟，刷新令牌 30 天；设备撤销使两者失效。

## 工程约束

- 中文注释与技术文档；禁止格式化无关文件。
- 所有公共接口更改同步生成 OpenAPI 与 Schema，并增加实际行为测试。
- 数据库结构通过版本迁移变更；禁止启动时 `create_all` 或修改历史迁移。
- 单元测试使用临时 SQLite；RLS、事务隔离和事件系统必须另用 PostgreSQL/NATS 验证。
- Provider 的 SDK/模型版本、Digest、许可证与硬件要求在生产启用前单独核验。
- 错误记录类型和关联 ID，不记录第三方原始异常正文。
- 完成状态只允许“代码完成”“集成通过”“真机通过”“生产通过”；不能以空接口计入完成。

## 后续扩展顺序

先补齐记忆派生索引消费者和删除对账，再实现完整隐私检测链、多步骤运行器与预算，随后完成实时语音、后台同步、APNs 和生产沙箱。不能因 Provider 已有适配代码就跳过这些核心依赖。
