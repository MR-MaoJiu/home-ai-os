# 部署与运维

本文针对当前仓库的开发与自托管部署。所有终端命令在仓库根目录执行；配置目录、证书、模型与安卓设备属于家庭服务器，不能照搬其他家庭的凭据。产品与流程见 [README](../README.md)。

## 先确定运行条件

- Python 3.12+、Docker Compose v2、Node.js 22；原生 iOS 构建还需要 macOS、Xcode、XcodeGen 和自己的签名配置。
- Mac 可运行支持 Metal 的本地模型；容器承载 PostgreSQL、NATS 和 OPA。推理内存取决于所选权重和上下文。
- 仓库提供开发 Compose 与发布 Dockerfile，尚无完成家庭生产隔离验收的一键生产集群。不要把镜像构建成功当作生产交付。
- 本地使用无需注册 Home AI Connect。远程平台、APNs、模型、邮件和家居分别配置，未配置的可选能力不会自动变为可用。
- 自动备份默认关闭。升级前是否备份由部署者决定；不要删除数据或重新生成主密钥来修复配置问题。

## 开发与部署

需要 Python 3.12+、Docker、Node.js；iOS 另需 Xcode 与签名配置。以下为开发环境启动方式。

作为家庭服务器的电脑需要保持运行和网络可达。显示器熄屏与整机睡眠不同；Mac 进入睡眠后，模型、Worker 与设备连接都会暂停，唤醒时任务可能已经到期。系统睡眠期间的请求超时不能只归因于模型或安卓设备，应同时核对主机电源日志。

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock
.venv/bin/pip install --no-deps -e .
.venv/bin/python scripts/dev_env.py
docker compose --env-file .env.local -f deploy/compose.dev.yml up -d
.venv/bin/python scripts/migrate.py --runtime
.venv/bin/homeai init-key
.venv/bin/python scripts/tls.py
npm --prefix admin-web ci
npm --prefix admin-web run build
```

`init-key` 只在首次安装执行，保留已有主密钥与 `.env.local`。升级前由用户决定是否手动备份；迁移不会自行开启备份或清空资料。旧版本运行增量迁移及所需的历史导入：

```sh
.venv/bin/python scripts/migrate.py --runtime
.venv/bin/python scripts/migrate_chat_history.py
```

当前迁移链截至 `0033`，包含安卓执行、语音通话、加密备用通道派发回执和设备自动审核字段。升级现有安装时先停止旧 API 和 Worker，完成增量迁移并构建管理端后，再统一启动新版本；保留原主密钥、配对、数据库和本机策略。不要用重新初始化代替升级。iOS 也需重新构建安装，旧客户端不会自行获得新的界面与同步行为。

分别启动 API 和后台服务：

```sh
.venv/bin/uvicorn homeai.api:create_app --factory \
  --host 0.0.0.0 --port 58443 \
  --ssl-keyfile state/tls/server.key --ssl-certfile state/tls/server.crt
.venv/bin/python -m homeai.worker
.venv/bin/python -m homeai.memory_worker
PYTHONPATH=server .venv/bin/python scripts/run_media_worker.py
PYTHONPATH=server .venv/bin/python scripts/run_notification_worker.py
# 使用家居事件订阅时另行运行
.venv/bin/python -m homeai.home_observer
```

媒体 Worker 必须与服务端一起运行；安装包或容器也可执行 `homeai worker --service media`，不依赖源码目录中的脚本。未运行时“部署检查”会明确显示附件解析未就绪，不能把已上传当作已解析。分块固定为 1 MiB，下列限制可在家庭服务器的 `.env.local` 中调整，保存后重启 API 与媒体 Worker，客户端通过 `/api/v1/uploads/limits` 读取当前值：

| 配置 | 默认值 | 含义 |
|---|---|---|
| `HOMEAI_MEDIA_IMAGE_MAX_BYTES` | `20971520` | 图片最大 20 MiB |
| `HOMEAI_MEDIA_FILE_MAX_BYTES` | `52428800` | 文件最大 50 MiB |
| `HOMEAI_MEDIA_VIDEO_MAX_BYTES` | `209715200` | 视频最大 200 MiB |
| `HOMEAI_MEDIA_VIDEO_MAX_SECONDS` | `600` | 视频最长 10 分钟 |

首次初始化管理员：

```sh
.venv/bin/homeai bootstrap --name 家庭管理员
.venv/bin/homeai web-setup --user <用户ID>
```

访问 `https://<家庭服务器地址>:58443/admin/`，配置家庭地址、模型和成员后生成二维码。开发证书默认仅适用于本机；部署时配置实际入口与证书，不关闭证书验证。打开 `ios/HomeAI.xcodeproj` 设置签名后运行。

模型权重不随仓库分发。Provider 启动与注册脚本位于 `scripts/`，固定版本配置位于 `providers/manifests/`。加密备份、主密钥和恢复演练需按实际部署环境配置。

### 客户端通知部署

站内通知持久保存在家庭服务器，登录设备按权限读取和标记已读。需要手机在应用退出或后台时收到系统通知，还需为自己的 iOS 应用配置 Apple Push Notifications：

直接连接 APNs 的部署方式适用于使用自己 Apple Developer 团队签名的 iOS 应用；自编译用户填写自己的 Team、Key 和 Bundle ID。官方发行应用的 APNs 私钥不能下发给自托管家庭服务器，官方推送代理尚未实现，不能用本部署配置替代官方应用的推送服务。

1. 在 Apple Developer 为应用标识开启 Push Notifications，并准备 APNs 签名密钥；iOS 签名描述文件和推送环境必须匹配。
2. 打开管理后台“通知配置”，填写 Key ID、Team ID、App Bundle ID，选择 `.p8` 私钥文件，勾选启用并保存。私钥加密保存在家庭服务器，页面只显示已配置状态；以后不选择新文件会保留原密钥。关闭系统推送会保留凭据和站内通知，不会回退到环境配置重新启用。

   也可在尚未通过后台配置时使用本机 `.env.local`：私钥文件限制为运行服务的账户可读（例如权限 `0600`），设置以下变量，不提交密钥或实际值：

   | 变量 | 内容 |
   |---|---|
   | `HOMEAI_APNS_KEY_FILE` | 本机 `.p8` 文件路径 |
   | `HOMEAI_APNS_KEY_ID` | APNs Key ID |
   | `HOMEAI_APNS_TEAM_ID` | Apple Developer Team ID |
   | `HOMEAI_APNS_TOPIC` | 当前 iOS 应用的 Bundle ID |

3. 在项目根目录启动通知投递进程：

   ```sh
   PYTHONPATH=server .venv/bin/python scripts/run_notification_worker.py
   ```

4. iOS 完成配对并允许通知后，将当前设备的推送令牌登记到家庭服务器。管理后台显示配置与通知进程状态；这些检查仅验证配置结构和进程在线，不代表 Apple 接受请求或手机收到通知。使用真实设备分别验收前台、后台及网络切换。

APNs 只接收固定提示与通知标识，不接收家庭业务正文。个人通知投递到本人注册设备，家庭自动化通知投递到本家庭有效成员设备；客户端认证后再获取可见详情。未配置 Apple 凭据、未启用 Worker 或未获得用户系统授权时，不能承诺系统推送到达；站内记录仍可在重连后读取。


### 备份设置与执行

自动备份默认关闭，不会因为部署、打开页面或保存位置就自行创建归档。管理后台“备份与恢复”提供以下设置：

- **保存位置**：填写家庭服务器上的绝对目录路径，不是浏览器所在电脑或 iPhone 的目录。
- **频率**：仅手动、每天、每周或自定义小时间隔。选择定时频率后，还需显式启用定时备份并保存。
- **立即备份**：按已经保存的位置提交一次备份任务，由服务器执行；修改设置后先保存，再手动执行。
- **状态与归档**：展示备份进程、下次计划、最近执行结果和当前目录的真实归档。排队或运行中不等于备份成功。

在项目根目录启动执行进程：

```sh
PYTHONPATH=server .venv/bin/python scripts/run_backup_worker.py
```

当前归档执行器使用本仓库开发 Compose 的 PostgreSQL（localhost／127.0.0.1:55432），按实际运行配置选择数据库；其他数据库部署会明确拒绝执行，避免备份错库。

关闭定时备份会停止后续定时任务，不删除已保存的归档。归档包含媒体密文、业务数据库、模型配置及相关状态。恢复必须提供备份外独立保管的最新删除日志和记忆遗忘日志（`--deletion-journal`、`--memory-forget-journal`），先重放墓碑并清除已删除媒体，作废恢复出的临时资料授权与云端批准，再开放访问；从未遗忘时也需明确提供空的遗忘日志。备份密钥、数据主密钥与日志应独立保管。恢复仍在家庭服务器本机进行，管理网页不会直接覆盖业务数据。


## 新电脑启用内置服务

Provider 数据库为空表示尚未登记服务，不需要复制其他电脑的数据库或凭据。打开“模型与凭据”即可看到内置目录：

- **联网搜索**：自建 SearXNG，固定容器镜像，默认聚合 Bing、Yahoo 与 Wikipedia。需要安装并启动 Docker。它不维护完整的互联网网页索引；获准的公开搜索词会发送给这些上游引擎，私人资料和家庭凭据不会随搜索请求发送。单个引擎故障时保留其他引擎取得的真实结果，并提示覆盖范围。
- **本地模型**：Qwen3 0.6B Q8（下载约 0.64 GB）或 Qwen3 4B Q4（约 2.50 GB）。实际运行还需要额外内存；0.6B 适合轻量验证，复杂工具规划优先选 4B。先按 [llama.cpp 官方指南](https://github.com/ggml-org/llama.cpp/blob/master/docs/build.md) 安装 `llama-server` 并加入 PATH。模型来自 [Qwen 官方 GGUF 仓库](https://huggingface.co/Qwen/Qwen3-4B-GGUF)，下载固定提交的文件并校验 SHA256。

除了 API、任务 Worker，在项目根目录启动内置部署器：

```bash
PYTHONPATH=server .venv/bin/python scripts/run_builtin_services.py
```

然后在“模型与凭据”选择服务与模型大小，点击“启用／应用选择”。部署器负责下载和启动；界面显示等待部署、启动中、可用或具体失败原因。只有实际健康检查通过才登记为可用。部署器未运行时会明确提示，申请不会伪装成已经启动。重启机器后需要将此进程与其他服务一起启动；首次下载需要访问模型仓库和容器仓库。停用会禁止 Core 调用；SearXNG 容器可继续存在供本机使用，若不再需要可在服务器执行 `docker compose -f deploy/compose.searxng.yml stop`。

内置部署器是可信本机运维进程，只接受固定目录选项，不接受网页提交的 Shell 或任意下载 URL。单独使用内置服务时，API 无需获得 Docker Socket；启用下述 Shell 后，可信 Core 执行器和管理端环境检查需要连接本机 Docker，任务容器始终不获得 Docker Socket。当前生产隔离尚未验收，生产模式仍拒绝通过开发部署器启用。

## 成员安卓执行设备

### 使用流程

每位成员可绑定一台专属安卓真机或已启动的官方模拟器，账号与设备归属保持独立。家庭后台“成员与设备 → 安卓执行设备”管理设备绑定和 AI 可操作的应用，不展示成员屏幕。AI 实际使用设备时，iOS 在聊天页右上角展示手机画面，可关闭或进入全屏；全屏悬浮面板提供系统画中画入口，切到其他 App 后仍可观看。设置、聊天小窗、全屏和系统画中画复用同一个视频会话，不因视图切换重建连接。

1. 本机管理员登记 ADB 和专用安卓设备，在家庭后台绑定成员并填写 AI 应用范围。
2. 成员正常对话提出需求，服务端判断使用搜索、资料工具还是安卓 App；仅绑定设备不会让所有任务都改走安卓。
3. 安卓任务取得本次控制权后打开获准 App，逐步观察与执行；客户端按实际任务状态展示手机画面。
4. 普通点击、导航、滚动和非密码输入由 Core 检查实际控件后直接执行。需要密码、验证、本人确认的提交操作，或确实无法继续时，原任务暂停并显示协助卡片；可打开安卓全屏处理，再点击“处理完成，继续任务”。密码不通过聊天收集。
5. 协助完成后重新验证设备与权限，读取新画面再规划，不重放接管前的坐标。普通主动接管仍会停止旧 AI 任务；只有绑定到原任务的有效协助卡片可以恢复该等待任务。关闭观看不等于处理完成或取消任务。

画中画只用于观看，回到全屏才可接管。进入只读小窗会释放本人持有的人工控制权，关闭画面不会取消服务端 AI 任务；同一任务被用户关闭后不会反复自动弹出。人工接管时只保留安卓画面和可拖动、收起的悬浮面板，提供暂停、返回／主页、文字输入等操作。黑边、面板和小窗按钮不透传触控。

家庭服务通过本机固定 ADB 执行器控制设备，调试端口不向公网发布。屏幕使用独立 H264 WebRTC 视频会话，协商经过已有签名家庭 API；实时画面、声音和原始触控使用独立直连通道，未接入 HTTP 密文备用通道，禁止 TURN。安卓通过固定版本 scrcpy 4.1 调用硬件编码器连续输出视频，默认最长边 1280、目标 30 帧／秒、4 Mbps；家庭服务器直接转发编码包，不再每半秒截一张 PNG 或重复编码。实际流畅度受设备、家庭上行和直连网络影响，断流会停止操作并显示原因。

静止画面允许长期没有新帧，设备健康和权限通过独立检查维持，不以无新帧直接判定断线。触控失活只取消输入，视频继续只读播放；“恢复触控”可在同一视频连接重建控制通道，不重放旧操作。系统画中画播放真实远端视频，不以通话或静音音轨维持后台；已有视频且观看未关闭时，切后台会尝试启动系统画中画；未能启动或保持画中画时暂停观看。

Android 11 及以上可接收设备系统声音，iOS 悬浮面板提供声音开关，纯播放不会开启手机麦克风。声音通过独立 Opus 音轨传输，不保存录音；设备或应用不允许采集时保留视频并显示具体原因。Android 10 及更早系统在当前采集方案下只提供画面，不会用麦克风代替系统声音。支付验证、受保护媒体及部分应用可能限制画面或音频，不能绕过其保护。

Android 11 启动声音采集时需要先解锁；其他版本也须满足设备与应用的实际采集条件，详见 [兼容性说明](来源与兼容性.md)。系统画中画不会解锁安卓，也不保证 iOS 被强制退出或网络不可达后继续播放。

实体熄屏控制默认关闭，自动亮屏与断线恢复尚未完成机型兼容性验收。未启用时不会启动电源控制进程，不影响无线连接、投屏和触控；不能把系统返回的电源模式当作实体屏幕已亮起的保证。

人工接管后，画面区域连续传递按下、移动、抬起和取消事件，支持点击、双击、长按、拖动及最多五指的缩放、旋转手势。触点使用独立、有序的直连通道，移动事件最多每秒 20 次；实际效果取决于安卓应用是否支持对应手势。打开悬浮菜单或弹窗、进入后台、退出、旋转或失去控制权时取消当前手势，不补发点击，也不重放断线期间的操作。安卓触控桥另有超时释放机制，避免网络中断后留下按住状态。

控制权默认暂停。服务端根据任务选择原生能力或安卓 App：公开资料查询优先搜索等已配置能力，确实需要 App 内操作时才使用成员设备。新的安卓任务可从暂停状态自动取得 AI 控制权，并绑定任务与控制版本；不会抢占本人正在操作的设备。人工接管与 AI 操作共用跨进程互斥锁，接管后旧任务不能恢复，终态任务释放设备。人工操作租约为 15 秒，iOS 前台每 5 秒续约；进入画中画或后台会释放人工输入，断网不自动交回 AI。已派发但结果不明的输入不能自动重放，需查看设备状态后处理。

操作当前已打开页面时，Agent 先调用 `observe_android`；只有需要打开或切换应用时才使用 `open_android_app`。`operate_android` 的普通动作由 Core 根据真实控件、焦点、窗口、应用范围和控制权核验，执行前再次检查；模型自报“安全”不能放行。付款、删除、对外发送、权限授予等实际目标交本人确认和操作，页面无关位置出现这些文字不会自动阻断普通导航。

画面过期或目标变化且尚未派发时，服务端撤下旧动作并自动重新观察；连续无法确认目标时才请求协助。协助卡片和通知持久保留，重复点击继续只恢复一次；绑定变化、设备撤销、其他设备正在接管或存在未核对的操作时不能恢复。已派发但结果不明的动作仍须核对，不自动重试。

普通界面只生成加密的结构化内部任务资料，不混入记忆或业务数据列表；新投影使用脱敏后可出站策略，继续经过现有隐私网关，不再因每次观察都默认标为仅本地而重复确认。密码和验证内容先在本地观察阶段截断，原始截图不直接交云模型；健康、精确位置、其他成员资料、秘密及用户已标记的 `LOCAL_ONLY` 资料保留原授权边界。通用远控不代表所有应用已经完成交易适配。

### AI 应用范围与人工接管

AI 应用范围规则如下，**不限制本人手动接管**：

| 配置 | AI 权限 |
|---|---|
| 单独填写 `*` | 允许使用所有应用，仍执行任务权限与风险检查 |
| 留空 | 不提供安卓操作工具，禁止 AI 操作任何应用 |
| 每行一个包名 | 只允许对应应用，读取界面和执行前核对实际前台包 |

`*` 不能与具体包名混填；包名范围不是 Android 系统级应用沙箱。

### 本机登记与无线连接

首次启用：在专用安卓手机打开 USB 调试，由本人确认这台服务器的调试公钥，然后在家庭服务器本机登记固定 ADB 路径与设备序号：

```sh
adb devices -l
PYTHONPATH=server .venv/bin/python -m homeai.android_adb \
  --adb /绝对路径/adb --serial 替换为设备序号
```

策略保存在 `state/android-policy.json`，权限为 0600。网页和模型不能添加本机设备执行权限；多个设备可重复提供 `--serial`，登记操作增量保留已有设备、无线连接及输入法配置。随后在成员与设备页面绑定成员，并按上述规则配置 AI 应用范围。停用绑定保留归属记录，防止把仍有登录账号的旧设备直接分配给其他成员；跨成员复用应先在本机清除账号和设备数据。

无线连接也由家庭服务器本机登记，Android 与服务器需要在同一可信局域网，iPhone 仍可通过原有直连服务从外网访问。成员始终绑定原设备身份，USB 和无线切换不会新建成员设备；管理端显示实际连接方式。Android 10 及更早系统需要先通过 USB 授权，再启用传统 TCP 调试：

```sh
PYTHONPATH=server .venv/bin/python -m homeai.android_wireless legacy-enable \
  --serial 替换为原设备序号 --endpoint 替换为手机局域网IP:5555 \
  --allow-legacy-tcp --prefer-wireless
```

传统无线 ADB 不加密，只适合可信局域网，不能做公网端口映射。手机重启后可能需要重新接 USB 启用。Android 11 及以上可在开发者选项开启“无线调试”，使用手机显示的配对端口与连接端口分别登记；配对码仅在本机终端隐藏输入，不进入命令参数、配置或日志：

```sh
PYTHONPATH=server .venv/bin/python -m homeai.android_wireless pair \
  --serial 替换为已登记设备序号 \
  --pair-endpoint 替换为手机IP:配对端口 --endpoint 替换为手机IP:连接端口 \
  --prefer-wireless
```

`--prefer-wireless` 允许 USB 仍插着供电时优先走无线数据连接；省略则优先 USB。每次选路核对设备身份，并固定本次执行的 ADB 传输，指令结果不明时不换路重发。地址变化后使用 `connect --serial 原设备序号 --endpoint 新地址:连接端口` 重新核对登记；不会扫描网络或连接未知设备。查看与撤销方式：

```sh
PYTHONPATH=server .venv/bin/python -m homeai.android_wireless status
PYTHONPATH=server .venv/bin/python -m homeai.android_wireless disable --serial 替换为原设备序号
```

撤销无线保留成员、USB 授权和输入法配置；关闭设备监听失败会明确说明，需要在手机中关闭无线调试。配对和支持情况以真实设备验证为准，不能将 Android 10 传统 TCP 连接标成 TLS。

### 视频、手势与中文输入组件

连续视频需要先安装固定版本采集组件，连续手势需要构建第一方触控组件：

```sh
.venv/bin/python scripts/android_media.py install
.venv/bin/python scripts/android_input.py build
```

视频安装器校验官方发行物的固定 SHA256，将组件及上游许可保存在 `state/android-media/`；仅通过私有 Unix socket 与已授权设备通信，不开放媒体 TCP 端口，关闭 scrcpy 自带控制与剪贴板同步。触控构建输出 `state/android-input/homeai-touch.jar`，服务端通过 ADB 私有管道注入系统触点。首次连接会预热组件，准备完成后才允许触控；组件缺失或系统不支持时明确报错。原始多指通道仅供本人已接管的 iOS 使用，AI 仍通过服务端动作校验流程执行。连续画面的短期凭据与 AI 截图摘要分开维护，视频刷新不会让模型跳过截图校验。

中文输入使用仓库内的 `android-input/` 第一方输入组件：没有联网权限，不读取已有输入内容，通过仅调试端可使用的受保护广播提交文字。构建脚本使用 Android SDK 35 与 build-tools 35.0.0，可通过 `--sdk`、`--java` 指定本机路径。由本机管理员明确安装并启用后，再将对应设备登记到 `--ime-serial`：

```sh
.venv/bin/python scripts/android_input.py install --serial 替换为设备序号
PYTHONPATH=server .venv/bin/python -m homeai.android_adb \
  --adb /绝对路径/adb --serial 替换为设备序号 --ime-serial 替换为设备序号
# 需要恢复原手机键盘时：
.venv/bin/python scripts/android_input.py restore --serial 替换为设备序号
```

未安装中文组件时只开放 ADB 能可靠输入的字符，并明确报错；不会把输入请求已发送冒充文字已写入。安装文件、本机签名密钥和设备配置均保存在忽略的 `state/`，不进入公开仓库。

### 连接与任务排查

| 现象 | 检查方向 |
|---|---|
| 静止页面长时间无新帧 | 新版不会仅因无新帧断开。检查设备健康、鉴权或 ICE 错误，不把低帧率等同于掉线 |
| 能看画面但不能操作 | 先确认本人已接管；触控通道失活时使用“恢复触控”，在原视频连接重建，不重放旧手势 |
| 无线设备离线 | 在服务器查看 `android_wireless status`；确认同一可信网络、手机已解锁且调试授权有效。地址变化后重新登记连接地址 |
| App 切后台后不再显示 | 已有视频时切后台会尝试画中画；未成功启动则暂停。可回前台从全屏悬浮面板手动开启，并确认视频已就绪 |
| AI 不操作已绑定手机 | 检查应用范围是否为空、设备是否正被本人接管，以及任务实际是否需要安卓能力 |
| 模型超时而人工操作正常 | 在“模型与凭据”分别验证文字与工具能力；设备链路成功不能证明云规划成功，不自动切换模型或重放操作 |
| 画面黑屏或没有声音 | 检查实体锁屏、受保护内容和系统版本。实体熄屏保持默认关闭；当前采集方案不支持 Android 10 系统声音 |

## 服务端 Shell

Shell 由服务端 Agent 编排和执行，iOS 负责提出需求、确认操作以及查看输出和附件。“模型与凭据 → 服务端 Shell”显示当前真实状态、工作区授权成员与宿主机动作；网页不提供任意命令执行入口。默认关闭，由持有服务器本机访问权的管理员配置。

| 执行方式 | 适用任务 | 权限边界 |
|---|---|---|
| 隔离工作区 | 处理文件、计算、运行 Shell 或 Python 脚本、生成交付文件 | 在固定镜像的临时容器内执行，仅接收本任务获准附件，无外网访问；不挂载宿主目录、Core 数据库凭据或 Docker Socket |
| 宿主机管理动作 | 管理已登记的服务、软件及系统文件 | 仅本机明确授权的家庭管理员可申请已登记的固定脚本，使用 Core 服务账号的系统权限；普通成员和模型不能新增或修改动作 |

隔离工作区明确区分 `shell` 与 `python` 两种执行语言。Python 由服务端固定使用隔离模式解释器执行，不把 Python 代码当作 Shell 命令，也不接受模型指定其他解释器路径。

模型提出任务后，Core 校验成员权限、输入资源与执行参数。隔离工作区只接收临时副本，关闭网络且不挂载宿主目录，因此在本机管理员已启用并授权成员后自动执行；新增、编辑或删除工作区文件不会修改服务器原始资料。宿主机命令默认在客户端展示完整指令供确认；成员明确开启设备自动审核后，可批准请求由服务器按该设备授权处理。批准绑定动作配置与具体参数；配置修改、权限撤回或审批过期后重新检查。执行有时限和输出限制，取消或超时会终止相应进程；结果不明的宿主机操作需要核对，不会盲目重试。执行报告与获准的生成文件作为私有附件保存并返回原会话，宿主机脚本与原始输出不自动发送给云模型。

宿主机审批卡片同时显示完整实际指令、执行位置与账号、输入输出范围、文件与服务影响及未能预先确定的影响。宿主机编辑或删除不会因 AI 自称“只读”而放行。本机固定动作可用 `--impact-summary`、可重复的 `--file-change` 和 `--service-change` 登记影响；AI 提供的 `impact_summary` 单独标为预计说明，不作为权限依据。影响说明也纳入审批摘要，改变后原审批失效。

本机策略文件默认是 `state/shell-policy.json`，仅允许文件所有者读写（0600），不要在脚本里保存密钥。容器镜像按本机固定 SHA256 使用。开发期 Mac 的普通 Docker 容器不等同于 Linux gVisor；生产隔离需要独立配置与验收。宿主机动作不经过容器隔离，不会自动提权；如果软件安装、服务管理或系统文件修改需要系统权限，由本机管理员另外设置明确的操作系统授权。

在项目根目录、使用运行 Core 的系统账号配置。首次初始化不会覆盖已有策略：

```bash
PYTHONPATH=server .venv/bin/python -m homeai.shell_configuration init
```

隔离工作区需要镜像中具有 `/bin/sh` 与 Python 3。可先在本机准备官方 Python 镜像并读取其固定 ID：

```bash
docker pull python:3.13-slim
docker image inspect --format '{{.Id}}' python:3.13-slim
PYTHONPATH=server .venv/bin/python -m homeai.shell_configuration enable-sandbox \
  --image sha256:替换为上一步完整镜像ID中的64位摘要 --member 替换为已授权成员ID
```

多个成员重复提供 `--member`；每次此命令都替换完整授权成员列表，不会自动授权全家。Linux 生产环境还须配置并验证 gVisor，在命令后加 `--runtime runsc`。运行任务时只使用已固定的本机镜像，不自动拉取标签所指向的新版本。管理页会核验当前成员授权并实际探测固定镜像中的 Shell 与 Python，“环境检查通过”不代替生产隔离验收。

登记经本机管理员审核的宿主脚本，再单独启用宿主管理。`--cwd` 是脚本固定工作目录，执行时不会接受模型提供的新目录或参数；`--timeout` 为 1 至 300 秒。以下路径与动作名称应替换为本机实际值：

```bash
PYTHONPATH=server .venv/bin/python -m homeai.shell_configuration add-host-action \
  --id check-service --title '检查服务状态' --description '读取指定服务的运行状态' \
  --script-file /绝对路径/check-service.sh --cwd /绝对路径/工作目录 --timeout 60
PYTHONPATH=server .venv/bin/python -m homeai.shell_configuration enable-host \
  --member 替换为获准宿主管理的家庭管理员ID
```

宿主管理与隔离工作区分别授权，不会因成员拥有家庭管理角色而自动开放整台机器的权限。登记会把当时的脚本内容写入策略文件；修改原 `.sh` 文件不会静默改变动作，需要重新登记。脚本应使用明确的可执行文件路径；启动或停止长期服务应调用系统服务管理器，直接后台启动的子进程会随本次任务回收。刷新管理端查看已登记内容，再在获准管理员自己的对话中提出执行需求并确认。`disable-host`、`disable-sandbox` 可停用对应能力，`remove-host-action --id check-service` 可移除动作；这些本机配置操作不会自动执行任何登记脚本。

## MCP 与 Skill

“模型与凭据”提供 MCP 地址和可选访问令牌，连接后读取真实工具目录。管理员核对参数契约，明确映射到 Core 能力，再保存并启用 Provider。目录指纹变化会停止调用，必须重新核对；不能把任意工具名称伪装成已有能力。现阶段支持 Streamable HTTP；stdio 服务使用 `scripts/run_mcp_stdio.py` 的固定配置桥接器，其对外协议为 Core HTTP Provider，不是 Streamable HTTP；不能把桥接地址直接填入 MCP 表单。当前网页 MCP 表单用于 Streamable HTTP 接入。工具仍由服务端 Agent 调度，并保留审批、审计和出站策略。

Skill 支持导入带 `name`、`description` YAML 头部的 `SKILL.md`。保存后默认停用；启用后作为本家庭 Agent 的处理指引，不赋予额外工具权限。当前入口执行指令型 Skill，不自动运行附带脚本或安装命令；需要 Shell 的任务仍遵循独立的本机执行策略，宿主机命令仍须经过审批契约；设备自动审核仅替代确认动作，不扩大本机策略。确定性、多步骤及定时任务由服务端自动化工作流执行，客户端只展示属于个人或家庭的规则与结果。Skill 可停用、删除，删除不会移除家庭资料或记忆。

## 部署凭据与动态码登录

以下三类凭据用途不同，不能互换：

| 凭据 | 来源 | 用途 |
|---|---|---|
| 数据加密主密钥 | `init-key` 生成于服务器 | 解密家庭资料；不得粘贴到网页登录或 iOS 验证器 |
| 初始化凭据 | 本机 `web-setup` / `web-recover` 输出 | 五分钟内、一次性初始化或恢复网页账号 |
| TOTP 动态码密钥 | 管理网页初始化成功后一次性展示 | 导入 iOS 验证器，离线生成每 30 秒更新的六位动态码 |

首次安装依次执行已有环境与数据库初始化步骤，再在项目根目录：

```bash
PYTHONPATH=server .venv/bin/python -m homeai.cli init-key
PYTHONPATH=server .venv/bin/python -m homeai.cli bootstrap --name 家庭管理员
# 将上一步输出的 user_id 填入以下命令，勿填写 pairing_token。
PYTHONPATH=server .venv/bin/python -m homeai.cli web-setup --user <user_id>
```

已有安装不要重复执行 `init-key` 或 `bootstrap`。`web-setup` 输出中的 `setup_ticket` 是此命令生成的网页初始化凭据，有效期 300 秒：打开家庭 HTTPS `/admin/`，选择“首次部署”，填写此凭据、用户名和备用密码。页面随后展示 TOTP 密钥，将其导入 iOS“设置 → 管理端动态码”，或标准验证器，并填入生成的动态码完成绑定。完成绑定前不能访问管理功能。凭据过期时重新运行 `web-setup`，不要删除数据库。

日常管理登录输入**用户名＋当前动态码**即可；已有客户端若同时提交密码，服务端仍校验该密码。登录有效期为 24 小时，有效期内的配置操作无需重复输入动态码；退出登录或撤销网页设备后立即失效。同一动态码不能重复使用；手动重新验证时需等待下一周期。连续错误会限流。iOS 在本机 Keychain 保存 TOTP 密钥，显示验证码前验证设备身份，离开前台隐藏；生成动态码不要求与家庭服务器连接。

丢失验证器时，只能由持有服务器本机访问权的人执行：

```bash
PYTHONPATH=server .venv/bin/python -m homeai.cli web-recover --user <user_id>
```

用新的一次性凭据完成初始化流程，重新绑定 TOTP；旧动态码密钥和旧网页会话随恢复失效。不要将初始化凭据、TOTP 密钥、主密钥、模型 API Key 或 `.env.local` 提交到 Git。

## 语音、来电与后台执行

转写、语音合成与语音对话是不同链路：转写需要已注册的 ASR Provider，朗读需要已注册的 TTS Provider；来电还需要 APNs/VoIP 配置、正确签名和语音执行器。启动脚本见 `scripts/run_whisper_backend.py`、`run_whisper_bridge.py`、`run_funasr.py`、`run_cosyvoice.py`；使用各脚本的 `--help` 与对应 Provider 清单，不把其他安装的本地 Token 复制进仓库。

通用 Worker 入口见 `homeai worker --help`；语音通话另行启动 `.venv/bin/python -m homeai.voice_worker`，与普通通知 Worker 分开运行。成员主动来电默认关闭，可配置免打扰时段和频率。CallKit 提供系统通话交互，不能用于普通聊天后台保活；接听成功、听到声音与双向对话须分别验收。自托管者使用自己的签名和推送密钥，项目不分发官方发行应用的 APNs 私钥。

## 日常排查与升级核对

| 现象 | 首先检查 |
|---|---|
| 重新打开应用连接慢 | 家庭主机是否休眠、可用局域网地址、协调平台连通性、是否允许加密备用通道；缓存不代表在线 |
| 会话显示刷新 | 同时更新 API 与 iOS；新协议将重验快照放进同一个响应，不先清空消息 |
| 反复索取健康数据 | 核对原请求是否 RESPONDED、已存指标与时间范围；新版先复用账本，再仅请求缺项 |
| Provider 已启用但工具不可用 | 检查服务进程、Manifest、实际能力验证和当前成员权限；在线探测不等于业务可用 |
| 朗读无声 | 检查 TTS 服务、音色接口、合成结果和手机音频状态；任务提交成功不等于音频播放成功 |
| 没收到提醒 | 核对是否真的创建了带到期时间与通知选项的记录，再查通知 Worker、APNs 与手机系统授权 |
| 审核关闭没有立即显示成功 | 等待服务器确认；离线或请求结果不明时不能显示“已关闭” |

更新代码后按需重新安装锁定依赖、构建管理端、运行增量迁移，并重启使用变更模块的进程；需要客户端改动时重新构建 iOS。主密钥、配对、数据库与本机策略应保留。只读健康检查可以使用本机证书：

```sh
curl --cacert state/tls/server.crt https://localhost:58443/health/live
```

该检查只证明 API 进程响应，不能代替模型、通知、端到端网络或恢复演练。
